#+title: Emacs Configuration

* Programming languages

Emacs 30 uses tree-sitter modes and Eglot for Java, Kotlin, JavaScript,
TypeScript, TSX, Vue, Python, C#, Ansible, YAML, and Angular HTML
templates.  Flymake diagnostics are enabled by Eglot.  Completion uses Emacs's standard
=completion-at-point= UI and is invoked manually with =M-TAB= or =C-M-i=;
Corfu or another automatic completion frontend is intentionally not installed.

Kotlin uses the external =kotlin-ts-mode= package with the shared Neovim
parser.  Both editors use JetBrains's official =kotlin-lsp= package from
Mason, exposed as the =intellij-server= executable.

Vue single-file components use =vue-ts-mode= with the shared Vue, TypeScript,
and CSS parsers.  Eglot runs Vue Language Server with hybrid mode disabled so
one server provides template and TypeScript support.  It prefers the project's
TypeScript SDK and falls back to the SDK installed with Mason's
=typescript-language-server= package.

Neovim owns the shared tooling installations:

- nvim-treesitter installs parsers in
  =~/.local/share/nvim/site/parser=, which Emacs adds to
  =treesit-extra-load-path=.  Library-name overrides map Emacs's usual
  =libtree-sitter-LANGUAGE.so= lookups to Neovim's =LANGUAGE.so= parsers for
  every configured tree-sitter language.
- Mason installs language-server executables in
  =~/.local/share/nvim/mason/bin=, which Emacs adds to =exec-path= and =PATH=.

Angular TypeScript, TSX, and template buffers use Rassumfrassum to present the
TypeScript and Angular language servers to Eglot as one connection.  The
nearest =angular.json= or =nx.json= defines the workspace.  Ordinary HTML does
not start Eglot, and React uses the regular JavaScript/TypeScript modes and
server.

Ansible files use a small =ansible-ts-mode= derived from Emacs's built-in
=yaml-ts-mode=.  Conventional playbook, role, inventory-variable, and Molecule
paths are recognized as Ansible; other YAML uses =yaml-ts-mode= and YAML
Language Server.  Ansible Language Server validation and =ansible-lint= are
enabled to match Neovim.

Inlay hints and on-type formatting are disabled to match Neovim.  Explicit
formatting is available through =SPC c f=, and there is no format-on-save hook.
Emacs 30's built-in Eglot does not implement semantic-token highlighting or a
code-lens execution command, so =SPC c x= and =grx= remain unimplemented.

The =eglot-hierarchy= package supplies call hierarchy temporarily.  When
upgrading to Emacs 31, remove that compatibility package and its outgoing-call
wrapper in favor of native Eglot call hierarchy.  Also reconsider sharing
nvim-treesitter parsers and evaluate =treesit-install-language-grammar= with
=treesit-auto-install-grammar=.

* Tests

Run the custom function tests against the installed configuration:

#+begin_src sh
~/.config/emacs/scripts/test
#+end_src

To run the tests from within Emacs:

1. Run =M-x load-file= and select =~/.config/emacs/tests/init-test.el=.
2. Run =M-x ert=, enter =t= for the test selector, and press =RET=.

The tests use ERT and call the custom functions directly. Keybindings are
documented in =docs/editor-keybindings.org= and are not duplicated in a
separate assertion file.
